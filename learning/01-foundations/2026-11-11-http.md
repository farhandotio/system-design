# 2026-11-11: HTTP

**Lesson:** [HTTP](https://freesystemdesign.com/#/http/learn)

## The Idea

HTTP is a way for a client and a server to talk. The client sends a request, and the server sends back a response. Loading a page, submitting a form, and calling an API all use this basic pattern.

## The Main Parts

- **Methods say what I want to do.** `GET` asks for something. `POST` sends data, often to create something. `PUT` replaces a resource, `PATCH` changes part of it, and `DELETE` asks to remove it. These are common conventions that help people understand an API.
- **Status codes say what happened.** `2xx` means success, `3xx` means redirect, `4xx` usually means there is an issue with the request or permission, and `5xx` means the server had a problem. For example, `200` is OK, `404` means not found, and `500` means server error.
- **Headers add details.** A request might include a cookie or authorization token. A response might say what kind of content it returned with `Content-Type`, or whether it can be cached with `Cache-Control`.
- **The body carries content.** It might contain HTML, JSON, an image, or other data.

```text
Client -> GET /profile + headers -> Server
Client <- 200 OK + headers + response body <- Server
```

## One Important Detail

HTTP does not remember earlier requests by itself. Cookies or tokens can carry information between requests, and the server checks them when needed. That is how a site can recognize a signed-in user.

## Takeaway

HTTP is a simple question-and-answer exchange with clear methods, status codes, headers, and sometimes a body. Next, I want to see how APIs use HTTP to share data with other programs.
